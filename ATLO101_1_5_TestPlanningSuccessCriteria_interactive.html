Test Planning & Success Criteria

Knowing how to run a test is important. Knowing what you are trying to prove with it -- and what passing actually looks like -- is more important. Without a test plan, a test is just activity. With one, it is verification.

Requirements Traceability

Every test in ATLO exists to verify a requirement. The requirement might be from the spacecraft specification -- "the RF subsystem shall transmit at a minimum data rate of X Mbps." The test exists to prove that requirement is met.

Requirements traceability is the documented link between each test and the requirement it verifies. It answers the question: how do we know the spacecraft meets its requirements? The answer is: we ran this test, it passed, and this test verifies requirement X. Without traceability, you can't demonstrate compliance -- traceability is not paperwork, it is proof.

Test Configurations and Prerequisites

Before a test can run, certain conditions must be in place. The spacecraft must be in the correct configuration. Required GSE must be connected and verified. Prerequisite tests must be complete. Safety inhibits must be verified in the correct state.

The test plan defines all of these prerequisites. Part of the ATLO engineer's job before executing any test is confirming that all prerequisites are met. Test readiness is not assumed. It is verified.
